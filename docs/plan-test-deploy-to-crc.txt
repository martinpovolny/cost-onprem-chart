SUMMARY (as of 2026-05-14)
================================================================================
All deployment steps (0–6) are complete on Apple Silicon (arm64) CRC.
Three test runs have been executed. The deployment is working but tests reveal
several categories of failure requiring follow-up.

WHAT WORKS:
  - Full stack deploys cleanly via `make crc-deploy` (Kafka, Keycloak, S4, Helm chart)
  - `make crc-test` (--no-ros --no-ui) runs ~144 tests in ~17 min, most passing
  - Ingress upload path, auth token flow, database, Valkey, celery workers all healthy
  - Automation is portable: arch auto-detected, amd64 needs no arm64 overrides

WHAT NEEDS FIXING:
  1. Keycloak restart loop (35+ restarts) — Vert.x event loop blocks under CPU
     contention on arm64/QEMU; liveness probe kills it. Cluster stabilises eventually
     but it degrades test reliability throughout the session.
  2. Gateway 503s — Envoy fails to reach koku-api under test load (TCP connect
     timeout × 2 retries = ~15s). Root cause not yet confirmed; koku-api responds
     fine when tested outside of concurrent test runs.
  3. test_all_critical_pods_running — hardcodes ros-api as critical; fails whenever
     ros.enabled=false. Easy fix: gate on the ros.enabled value.
  4. test_listener_kafka_connectivity — persistent Kafka broker disconnect in listener
     logs. Possibly Kafka restarting under memory pressure.
  5. test_cost_validation suite — errors because no cost data has been ingested.
     Needs an e2e upload run first.

KNOWN ARM64 LIMITATIONS (by design, not bugs):
  - ros-ocp-backend is amd64-only; ROS suite always skipped (--no-ros)
  - Default koku image is amd64-only; arm64 uses quay.io/martin_povolny/koku:latest
  - RHBK has no arm64 images; Keycloak uses community operator instead
  - Ingress image tag in values-crc-arm64.yaml expires 2026-05-18 — refresh needed

NEXT STEPS (priority order):
  1. Refresh ingress image tag before 2026-05-18 (see Step 5 notes for curl command)
  2. Fix test_all_critical_pods_running to respect ros.enabled
  3. Investigate Keycloak restart loop — consider tuning liveness probe or adding CPU
  4. Investigate gateway 503 root cause under concurrent test load
  5. Run e2e data ingestion flow (nise + upload) to enable cost validation tests

STEP 5 — Deploy the Helm chart
================================================================================
Status: DONE

  # Preferred: use the Makefile (auto-detects arch, selects correct values files)
  make crc-deploy

  # Or directly (arch auto-detected inside the script):
  ./scripts/deploy-to-crc.sh

  # Or with explicit env overrides:
  ARCH=arm64 KEYCLOAK_OPERATOR=community ./scripts/deploy-to-crc.sh

Notes:
  - Values files: values-crc.yaml (arch-agnostic resource overrides, both arm64+amd64)
    + values-crc-arm64.yaml (arm64-only: ros.enabled=false, koku image, ingress tag).
    deploy-to-crc.sh auto-detects arch and layers both files on arm64, just the base on amd64.
  - Default chart image (quay.io/redhat-services-prod/cost-mgmt-dev-tenant/koku:...)
    is x86_64-only. On arm64 CRC it runs under QEMU and segfaults during Django startup.
    Built koku_base:latest locally via `make docker-build` in the koku repo, tagged and
    pushed as quay.io/martin_povolny/koku:latest (2.12GB, native arm64).
  - All koku components reference .Values.costManagement.api.image via the
    cost-onprem.koku.image helper in _helpers-koku.tpl — a single image override suffices.
  - install-helm-chart.sh -f path must be absolute (script does `cd "$SCRIPT_DIR"` internally).
  - ros-ocp-backend is amd64-only; crashes under QEMU. ros.enabled=false in values-crc-arm64.yaml
    disables all 11 ROS templates. On amd64, ros.enabled=true (chart default).
  - Memory: node has 18GB but Keycloak+Kafka+system pods consume ~15GB of requests.
    All cost-onprem requests set to 64Mi in values-crc.yaml (limits unchanged).
    Template paths: ingress→.Values.resources.application, kruize→.Values.resources.kruize,
    database→.Values.resources.database (NOT .Values.{ingress,kruize,database}.resources)
  - Ingress image tag in values-crc-arm64.yaml expires 2026-05-18. Refresh:
      curl -s "https://quay.io/api/v1/repository/redhat-user-workloads/hcc-integrations-tenant/ingress/tag/?limit=5&onlyActiveTags=true"
  - Kruize (Java/JVM) needs ≥2Gi memory LIMIT (request stays at 64Mi). 512Mi causes OOM.
  - install-helm-chart.sh reports "[ERROR] ROS API pod not found" — expected on arm64.
